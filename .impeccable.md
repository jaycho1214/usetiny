## Design Context

### Users

General audience looking for simple, reliable browser tools without signing up for yet another SaaS app. They want to get in, do the thing, and move on. Context: quick tasks — jot a note, generate a QR code, edit a PDF. No onboarding, no accounts, no friction.

### Brand Personality

**Fast, minimal, quiet.**
UseTiny doesn't announce itself. It gets out of the way and lets the tool do the talking. Confidence through restraint — no decoration, no filler, no noise.

### Aesthetic Direction

- **Reference**: Linear — clean layout, monochrome palette, sharp typography, precise spacing, keyboard-first interaction, smooth motion
- **Departure**: Components should carry more visual weight than Linear's ultra-subtle approach. Bolder interactive elements — buttons, tabs, and cards should feel solid and tactile, not whisper-thin
- **Theme**: Monochrome. No accent color. Let contrast, weight, and spacing create hierarchy instead of color
- **Typography**: Geist Sans (system). Hierarchy through size and weight, not color
- **Anti-references**: Colorful SaaS dashboards, playful/rounded aesthetics, anything that feels like it's trying too hard to be friendly

### Design Principles

1. **Disappear into the task** — The tool should feel like an extension of the user's intent, not a product demanding attention. Chrome is minimal. The content area is the product.
2. **Earn every pixel** — No decorative elements. Every border, shadow, and spacer must serve a functional purpose. If it doesn't help the user, remove it.
3. **Bold where it counts** — Interactive elements (buttons, tabs, inputs) should feel solid and present. Quiet doesn't mean invisible — controls need enough weight to be confident and obvious.
4. **Keyboard-first, mouse-friendly** — Power users get shortcuts. Everyone else gets clear click targets. Both paths are first-class.
5. **Local and honest** — Everything runs in the browser. No spinners waiting for servers. No "syncing..." states. Instant feedback, always.
